## 1. How to Read This Document

Written for AI coding agents working on this repo. It states the stack, the exact commands, the module boundaries, and the conventions to follow — so you do not need to re-explore the tree. Update it if a module is added, a model backend is swapped, or tests are introduced.

## 2. Overview

`movie-subtitles` turns a video/audio file into a translated `.srt` file, and optionally into a dubbed video with a synthesised translated audio track. Engine values name vendors, not pipelines, and each of the three stages (ASR, translation, TTS) is independently selectable, plus a fourth path that bypasses this repo's pipeline entirely:

- **`--asr-engine {local,elevenlabs,openai}`**, **`--translation-engine {local,anthropic,openai}`**, **`--tts-engine {elevenlabs,openai}`** each independently pick a backend. `--engine {local,elevenlabs,openai}` is a shorthand that sets all three stages when the per-stage flags are not given.
- **`--engine local`** (default, unchanged from the original tool): faster-whisper ASR → local MADLAD400 T5 translation → `.srt`. Local and offline after model download **as long as `--voice-match off` is passed** — any other `--voice-match` value (`auto` is the default) now runs a `pyannote.audio` speaker-diarisation pass over the source audio, which contacts Hugging Face on first use (see section 5 principle 3 and section 7). No TTS stage; `--dub` with a `local`-resolved translation stage is allowed but logs a loud warning (MADLAD400 ignores the length budget, so timing-drift fitting degrades to TTS-rate-only).
- **`--engine openai`**: OpenAI ASR (`whisper-1`) → OpenAI chat-completions translation → `.srt`, optionally followed by `--dub` using OpenAI TTS (`tts-1` by default — see section 3 for why).
- **`--engine elevenlabs` alone raises `ValueError`** before any work starts: ElevenLabs has no standalone text-translation endpoint, so `--translation-engine {anthropic,openai,local}` must be passed explicitly alongside it — e.g. `--engine elevenlabs --translation-engine anthropic` reproduces the old pre-rename behaviour (Scribe ASR → Claude translation → optional `--dub` with ElevenLabs TTS).
- **`--managed`**: calls the ElevenLabs Dubbing job API (create → poll → download) directly. No local ASR/MT/TTS code runs; this is the "buy" side of a build-vs-buy comparison against the hand-rolled `elevenlabs --dub` path.

**Mixed-vendor pipelines are expected, not just tolerated.** Any combination of the three per-stage flags is valid as long as it satisfies the `--dub` guard (TTS must resolve to `elevenlabs` or `openai`; a translation stage resolving to `local` is allowed under `--dub` but logs a loud warning, since MADLAD400 ignores the length budget) — e.g. Scribe ASR + OpenAI translation + OpenAI TTS. The `elevenlabs`-shorthand translation gap (no standalone text-translation endpoint; translation exists only bundled inside the Dubbing job) was a finding during implementation, not a starting assumption. See README.md "Which stages are ElevenLabs, and which are not" for the full explanation and reasoning.

**Known gap, resolved:** the original README advertised burned-in per-frame subtitles. That was never implemented and has been removed from the README as of this port. `.srt` and (with `--dub`) a muxed dubbed video are the only output paths. Do not assume frame-rendering code exists.

**Resolved:** the `--dub` timing model is scene-anchored, not per-segment. Segments are grouped into scenes by inter-segment silence gap (word-level when ASR provides word timings); each scene's clips are pinned to their own ASR start and float forward only on overrun, and a scene whose accumulated drift against its source *speech* time exceeds tolerance goes through a bounded corrective re-synthesis loop (`--dub-correction-passes`, default 3) rather than a single fixed retry. See section 5 and section 10.

## 3. Technology Stack

- **Python** — `requires-python = ">=3.10"`. Type hints use `X | Y` union syntax (3.10+).
- **faster-whisper** — local ASR (CTranslate2 Whisper). Default model `large-v3`. `local` engine only.
- **transformers** (+ **torch**, **sentencepiece** via T5Tokenizer, **accelerate**) — local machine translation. Default model `jbochi/madlad400-3b-mt`, loaded with `device_map="auto"`; `accelerate` is required at runtime because `transformers` only accepts `device_map="auto"` in `from_pretrained` when `accelerate` is installed — without it, `--engine local` cannot translate. `local` engine only.
- **elevenlabs** (official Python SDK) — Scribe ASR (`speech_to_text.convert`), TTS (`text_to_speech.convert`), and the Dubbing job resource (`dubbing.create` / `.get` / `.audio.get`). `--asr-engine`/`--tts-engine elevenlabs` and `--managed`.
- **anthropic** (official Python SDK) — Claude-backed translation (`messages.create`), default model `claude-sonnet-5` (`providers/llm.py:_MODEL`). `--translation-engine anthropic` only.
- **openai** (official Python SDK) — `audio.transcriptions.create` (ASR, `whisper-1`), `chat.completions.create` (translation, `gpt-5.6-terra`), `audio.speech.create` (TTS, default `tts-1` — not `gpt-4o-mini-tts`, which accepts but silently ignores the `speed` parameter, making the dub path's rate-fitting lever inert; `gpt-4o-mini-tts` stays reachable via the `OpenAISpeak` constructor argument). `--asr-engine`/`--translation-engine`/`--tts-engine openai`. Module is `providers/openai_.py` (trailing underscore) so it doesn't shadow the `openai` SDK import inside it.
- **ffmpeg / ffprobe** (external binary, not a Python dependency) — required for `--dub` only: `ffprobe` is the last-resort tier for measuring a synthesised clip's length, `ffmpeg`'s `silencedetect` filter is the default tier for measuring its real speech span, and `ffmpeg` assembles the per-segment clips onto a silent timeline (trimming each clip's leading/trailing padding via input `-ss`/`-t`) and muxes the result over the source video. Not required for `.srt`-only runs (either engine) or for `--managed` (ElevenLabs renders server-side).
- **demucs** — source separation for `--separate-background`: `separate.py:Separate` drives `demucs.api.Separator` (`htdemucs`) to split the source audio into vocals/accompaniment stems, feeding the accompaniment stem to `mux_dub` as the ducked bed. `Separator` owns the decode and resampling, and `demucs.audio.save_audio` the write, so no second audio-I/O library is a dependency and no intermediate extracted wav is written. `demucs.api`/`demucs.audio` are imported lazily inside `Separate`'s `__init__`/`separate()`, so a run without `--separate-background` never pays their (or torch's) import cost, even though `demucs` is a hard runtime dependency in `pyproject.toml`. `__init__` prefers CUDA when available.
- **pyannote.audio** (`>=4.0`, pinned — unconstrained resolution lands on 3.4.0, too old) — speaker diarisation for `--asr-engine local`/`openai`, neither of which diarizes natively. `providers/pyannote_.py:Diarize` builds a `pyannote/speaker-diarization-community-1` pipeline once in `__init__` (CUDA when `torch.cuda.is_available()`, else CPU — matching `separate.py`'s posture) and `diarize(fpath)` returns a time-sorted `list[Turn]`. Both `pyannote.audio` and `torch` are imported lazily, inside `__init__` only (`diarize()` needs no import of its own), so `--voice-match off` and `--asr-engine elevenlabs` (which diarizes via Scribe instead) never pay the import cost. The model is **gated**: first use needs a Hugging Face account, the model's conditions accepted at its model page, and a token in `HF_TOKEN` (the `huggingface_hub` standard), which `Diarize.__init__` reads via `os.environ.get("HF_TOKEN")` and passes explicitly as `token=` to `Pipeline.from_pretrained()`. `Diarize.__init__` translates a missing-token/unaccepted-gate failure (`GatedRepoError`/`RepositoryNotFoundError`/`HfHubHTTPError`, or `from_pretrained` returning `None`) into one actionable `RuntimeError` naming `HF_TOKEN` and the model page, rather than letting an opaque 401/403 propagate. `Diarize` raises rather than catching runtime/inference failures, exactly like `separate.py`; `cli.py` is what decides whether that degrades the run (yes — warn and continue with every `speaker=None`) or an `ImportError` propagates (yes — a broken install fails the run). **Platform consequence:** `pyannote.audio>=4.0` collapses `uv.lock`'s previous two-branch torch pin (2.2.2 for `x86_64` macOS, 2.13.0 elsewhere) to torch 2.13.0 only, which has no `x86_64` macOS wheel — Intel Mac support is dropped as a result, a breaking change accepted for one install story rather than an optional extra. `transformers` and `demucs`'s own pins are unmoved by this resolution.
- **tqdm** — progress bar over segments during SRT writing.
- **argparse** (stdlib) — CLI argument parsing. No Click/Typer.
- **uv** — dependency resolution, lockfile (`uv.lock`), venv, and tool install. **hatchling** — build backend.
- **ruff** — the only linter/formatter and the only CI gate. Dev dependency group `dev`.

                           # then configure_logging() applies MOVIE_SUBTITLES_LOG_LEVEL to this
                           # package's own loggers only (_PACKAGE_LOGGERS -- they are flat,
                           # "dub" not "movie_subtitles.dub", so there is no ancestor to set).
                           # Root stays INFO on purpose: raising it also enables vendor
                           # (httpcore/openai/anthropic) DEBUG, which drowns our own lines.
                           # cli.main() re-calls configure_logging() after _load_env(), so the
                           # variable also works when set in .env. Unset or unrecognised

  cli.py                  # argparse entry point + create_subtitles() orchestration, engine
                           # selection, translation-length-budget derivation (larger of
                           # source-text expansion ratio and duration-derived slot
                           # capacity), top-level error handling.
                           # Diarisation is orchestration only here (issue #27's algorithm now
                           # lives in movie_subtitles/diarize.py, see below): the
                           # needs_diarization guard in create_subtitles is the only place that
                           # decides whether diarisation runs at all (the resolved ASR engine
                           # not already diarizing natively, and voice_match != "off"), and
                           # _diarize_or_warn(fpath, asr_engine) is the single try/except that
                           # builds providers/pyannote_.py:Diarize, extracts a mono 16 kHz PCM
                           # wav from the source media via
                           # movie_subtitles/ffmpeg.py:extract_mono_wav() into a
                           # tempfile.TemporaryDirectory(), and hands that wav, not the source
                           # media, to Diarize.diarize() -- pyannote's torchaudio/torchcodec
                           # loader may not decode a video container the way demucs's
                           # ffmpeg-backed Separator can, and since a diarisation failure only
                           # degrades to a warning, feeding it a raw .mp4 risked the feature
                           # silently never working. Build, extraction, and diarize() all run
                           # inside that one try, up front -- before the (lazy) ASR segment loop
                           # starts -- with exactly one `except ImportError: raise` and one
                           # `except Exception` -> one WARNING + `[]` (every segment's speaker
                           # stays None), mirroring _dub_and_mux's handling of separate.py
                           # failures. The resulting `list[Turn]` is threaded into
                           # diarize.py:label_segments(segments, turns), which wraps the ASR
                           # segment generator with the actual merge/split/smoothing algorithm
                           # without materializing it
  diarize.py              # label_segments(segments, turns): lazily merges pyannote.audio
                           # diarisation Turns onto ASR Segments by temporal overlap, for
                           # --asr-engine local/openai (issue #27 -- neither diarizes
                           # natively, unlike elevenlabs/Scribe). A private _TurnCursor class
                           # holds the forward-only turn-index cursor as instance state
                           # (turns are start-sorted and spans are visited in ascending time
                           # order, so the cursor only ever advances -- O(words + turns), not
                           # O(words * turns)); its speaker_for() fast-paths the common
                           # single-overlapping-turn case in two local variables and only
                           # allocates a dict once a second distinct speaker overlaps a span,
                           # replicating max(overlaps, key=overlaps.get)'s first-seen-wins tie
                           # break exactly. _split_segment_by_speaker() splits a segment into
                           # one sub-segment per contiguous speaker run when segment.words is
                           # populated (word-level overlap, smoothing any word that overlaps no
                           # turn onto a neighbouring labelled word rather than letting it
                           # fragment its own run -- a segment with no labelled word at all
                           # stays entirely speaker=None), or labels it whole by majority
                           # overlap when words is None. Stays lazy end to end -- never does
                           # list(segments) -- so the caller's tqdm loop still drives ASR
                           # inference and the progress bar. Deliberately separate from
                           # providers/elevenlabs.py:ScribeTranscribe._group_words (Scribe's
                           # native per-word speaker_id split) -- the two are not unified
  srt.py                  # segment -> SRT block formatting (format_timestamp, format_block),
                           # lifted out of cli.py; provider-agnostic
  dub.py                  # scene-anchored TTS synthesis (_corrective_rate, synthesise_track):
                           # groups segments into anchor groups by inter-segment silence
                           # gap (word-level gaps when both segments carry `words`, else
                           # cue-boundary gaps), lays each group's clips out pinned to
                           # each segment's own ASR start (`max(segment.start,
                           # prev_placed_end)` -- floats forward only on overrun, so
                           # unused slack cannot pile up as trailing silence), and
                           # measures drift as synthesised speech total against summed
                           # source *speech* time (word-span when available), not
                           # wall-clock cue span. An initial pass synthesises every
                           # segment at 1.0x; a bounded correction loop then follows
                           # (`_MAX_CORRECTION_PASSES = 3`, wired to
                           # --dub-correction-passes) -- each pass re-synthesises only
                           # the segments of groups still outside `_DRIFT_TOLERANCE` at
                           # a shared per-group clamped rate, and a group drops out once
                           # back in tolerance or a pass fails to reduce its drift.
                           # Clip files are pass-discriminated
                           # (segment_NNNNN_pNN.mp3) so a rejected pass cannot leave its
                           # audio under a kept clip's stale offsets. The initial pass
                           # and every correction pass run as one flat cross-group batch
                           # over one bounded ThreadPoolExecutor (`max_workers`, wired to
                           # --dub-workers, default 1 = serial; argparse rejects values
                           # below 1). Each hands its per-group batches to `_resolve()`
                           # in one call, which flattens them before waiting, so on the
                           # first exception it cancels the still-queued tail across
                           # every group's batch in that pass (not just the failing
                           # group's) and re-raises the lowest-submission-index failure;
                           # results are collected by submission index so
                           # output/log order is independent of completion order. Real
                           # speech-span measurement itself no longer lives here -- it's
                           # delegated to the `aligner: AlignmentProvider` (required
                           # kwarg) built by cli.py:_build_aligner(). Returns
                           # `(out_path, speech_spans)`, where `speech_spans` is
                           # `_speech_spans()`'s coalesced, `_SPAN_PAD`-padded list of
                           # `(start, end)` placed-speech windows, threaded by
                           # `cli.py:_dub_and_mux` into `mux_dub(..., speech_spans=...)`
                           # so the original audio can be ducked only while the dub
                           # actually speaks
  mux.py                  # mux_dub(): overlays a finished audio track over the source video
                           # with ffmpeg, keeping the original audio (or, when
                           # `background_path` is given -- `--separate-background`'s
                           # separated accompaniment stem -- that instead) underneath
                           # rather than replacing it -- mixed in via `amix=normalize=0`,
                           # ducked to `duck_level` inside the caller's `speech_spans`.
                           # `duck_level` defaults to `None`, a sentinel `mux_dub`
                           # resolves itself to `_DUCK_LEVEL = 0.25` normally or
                           # `_SEPARATED_DUCK_LEVEL = 0.6` when `background_path` is
                           # given -- an explicit `--duck-level` always wins. Falls back
                           # to the old dub-only mapping when
                           # `ffmpeg.probe_audio_format()` returns `None` (no audio

                           # imports `torch` and `demucs.api` inside `__init__`, and
                           # `demucs.audio` inside `separate()`, so a run without the
                           # flag never pays their import cost. `__init__` constructs
                           # a `demucs.api.Separator` (`htdemucs`, on CUDA when
                           # available), which loads the model once;
                           # `separate(fpath, out_path)` hands the file to it,
                           # which decodes and resamples it
                           # itself, then sums every stem except "vocals" in place

                           # stem -- `mux_dub` re-targets the final output to the

                           # `Separator`/`save_audio` raises -- nothing is caught here;
                           # `cli.py:_dub_and_mux` is what degrades on failure, and owns
                           # the temp dir the stem is written into

## 5. Core Architecture Principles

These describe what the code actually does — follow them rather than importing conventions from elsewhere.

1. **Model/API wrappers are callable classes.** Every backend (`Transcribe`, `Translate`, `ScribeTranscribe`, `Speak`, `LLMTranslate`, `OpenAITranscribe`, `OpenAITranslate`, `OpenAISpeak`, `ManagedDub`, `Align`, `SilenceAlign`, `DurationAlign`, `FallbackAlign`) loads its client/model in `__init__`, exposes a named method (`transcribe` / `translate` / `speak` / `dub` / `align`), and defines `__call__` delegating to it. A new backend should follow the same shape.
2. **Providers implement Protocols, not base classes.** `providers/base.py` defines `ASRProvider`, `TranslationProvider`, `TTSProvider`, `AlignmentProvider` as `typing.Protocol`s (structural typing — no inheritance required). `cli.py` has four builders: `_build_asr_provider`, `_build_translation_provider`, and `_build_tts_provider` each pick a concrete class per the resolved per-stage engine value (`local`/`elevenlabs`/`openai`, vocabulary differing per stage — see section 7), and `_build_providers()` wraps the first two for the ASR+translation stages every invocation needs. These are the only places that pick a concrete class per engine; everything downstream (`srt.py`, `dub.py`) is written against the `Segment` shape and the Protocol signatures, not against any vendor concretely.
3. **`Segment` is the interchange type between ASR and everything downstream.** `providers/base.py:Segment(id, start, end, text, words=None, speaker=None)` — still constructible from the original four positional args. `words: list[Word] | None`, where `Word(start, end, text)` is a small frozen dataclass, carries per-word timings for backends that have them; `ScribeTranscribe` derives cue extents from `word`-type tokens only (Scribe's `spacing` tokens tile the timeline contiguously and would otherwise make every inter-cue gap read as exactly 0.00s). **`providers/local.py:Transcribe` and `providers/openai_.py:OpenAITranscribe` now populate `words` too** (`word_timestamps=True` / `timestamp_granularities=["segment", "word"]`, both requested unconditionally, not only when diarising) — this is what makes speaker-change cue splitting expressible on these engines, and it upgrades `dub.py`'s gap grouping to word-level for them as a side effect (a dub-timing shift on `local`/`openai`, even under `--voice-match off`, since populating `words` alone changes which grouping branch `dub.py` takes). `speaker: str | None` carries a diarized speaker label. `ScribeTranscribe` still populates it natively (Scribe's `diarize=True`, the constructor default). `Transcribe` and `OpenAITranscribe` do **not** diarize natively, but `cli.py` now labels their output too: whenever the resolved ASR engine doesn't diarize and `--voice-match != "off"` (`needs_diarization`), `cli.py:_diarize_or_warn(fpath, asr_engine)` builds `providers/pyannote_.py:Diarize` (`pyannote/speaker-diarization-community-1`), extracts a mono 16 kHz wav from the source media via `ffmpeg.py:extract_mono_wav()` — pyannote's torchaudio/torchcodec loader may not decode a video container directly — and calls `diarize()` on that wav once, up front, all inside one try/except so build, extraction, and diarize() degrade identically (one `except ImportError: raise`, one `except Exception` → WARNING + `[]`). `movie_subtitles/diarize.py:label_segments(segments, turns)` then merges the resulting `Turn` list onto each segment by temporal overlap inside the still-lazy ASR loop, using a private `_TurnCursor` to hold the forward-only turn-index cursor as instance state, and smoothing any word that overlaps no turn onto a neighbouring labelled word instead of letting it fragment its own run (a segment with no labelled word at all stays entirely `speaker=None`) — word-level overlap (splitting a segment into one sub-segment per contiguous speaker run) when `words` is populated, cue-level majority overlap otherwise. This algorithm — cursor, splitting, smoothing — lives entirely in `diarize.py` now, not `cli.py`; `cli.py` only builds the diarizer, extracts the wav, and calls `label_segments()`. `--voice-match off` skips this pass entirely on every engine: no diarisation runs, no pyannote/torch import happens, no segment is split on speaker change, and every segment's `speaker` stays `None`, exactly as before this feature — cue *count* and cue *text* are unchanged on every engine. Cue *timings*, however, are not guaranteed byte-for-byte on `--asr-engine local`: `providers/local.py` now requests `word_timestamps=True` unconditionally (see above), which switches on faster-whisper's DTW word-alignment pass regardless of `--voice-match`, and that pass can adjust a segment's own `start`/`end` marginally even when nothing is split or labelled. `ScribeTranscribe` normalises Scribe's word-level response into the same `Segment` shape faster-whisper yields (grouping words into segments on sentence-end punctuation, a max duration, a max character count, *or a speaker change* — see `providers/elevenlabs.py:_group_words`), so `srt.py` and `dub.py` never branch on which ASR backend produced a segment; `dub.py` does branch on whether `words` is populated, falling back to cue-boundary gaps when it is not, and `voices.py:resolved_voices` branches on whether `speaker` is populated, returning an empty (single-voice) mapping when no segment carries one. Splitting cues on speaker change is a visible behaviour change for every `--asr-engine elevenlabs` run, not just `--dub` — and now, via the diarisation pass above, for `--asr-engine local`/`openai` runs too, whenever `--voice-match != off`: a scene with dialogue between multiple speakers yields more, shorter `.srt` cues than before this feature, since a cue is flushed as soon as the diarized speaker changes. `--asr-engine openai` diarising additionally logs a WARNING: speaker labels are assigned by overlapping turns against `whisper-1` segment spans, and that engine's segment-timestamp defect (principle 6/section 11 below) makes such labels confidently wrong, not merely absent, on affected audio.
4. **Orchestration lives only in `cli.py`.** `create_subtitles()` is the single place that knows the pipeline order, chooses `--managed` vs. the local/elevenlabs transcribe→translate(→dub) pipeline, and computes the per-segment translation length budget (`_budget_chars`, the LARGER of two independently measured lower bounds: a per-target-language expansion-ratio term against source text length, and a duration-derived slot-capacity term against the measured median target-language speaking rate — see section 10 step 1). Individual providers know nothing about each other, about SRT, or about dubbing.
5. **Model/backend names and API keys are parameters or environment, never hardcoded at the call site.** Local model-name defaults live in *both* the class `__init__` signature and the argparse defaults; keep the two in sync when changing a default. API keys (`ELEVENLABS_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) are read once per provider via a `build_client()`-style helper and never accepted as CLI flags or written to a file. `.env.example` at the repo root lists all three as placeholders for local `.env` use; the filled-in file is never committed.
6. **Errors that reach `main()` from a known cause are user-facing, not tracebacks.** `build_client()` helpers raise `RuntimeError` naming the missing env var; `ManagedDub._poll_until_done` raises `TimeoutError` on a stuck job and `RuntimeError` on a failed job; `create_subtitles()` raises `ValueError` for: the `--dub`/`--managed` conflict, `--engine elevenlabs` with no explicit `--translation-engine` (ElevenLabs has no standalone text-translation endpoint), and `--dub` when the resolved TTS engine is not in `{elevenlabs, openai}` (a translation stage resolving to `local` under `--dub` is a `logger.warning`, not a `ValueError` — the run proceeds, degraded to TTS-rate-only fitting); `cli.py:_check_ffmpeg_tools()` raises `RuntimeError` up front if either `ffmpeg` or `ffprobe` is missing from `PATH`. Every provider that calls a vendor SDK (`elevenlabs.py`, `openai_.py`, `llm.py`, `dubbing.py`) also catches its SDK's own top-level error base (`ApiError` / `OpenAIError` / `AnthropicError`) at the call site and re-raises `RuntimeError(...) from exc`, so a vendor exception (e.g. a 429) reaches `main()` already as one of the caught types rather than as an uncaught vendor-specific class — this is what let `main()`'s tuple stay unchanged rather than needing to import and list every vendor SDK's error type. `cli.py:main()` catches `RuntimeError | ValueError | FileNotFoundError | TimeoutError | subprocess.CalledProcessError` around the `create_subtitles()` call, logs a one-line message, and exits via `raise SystemExit(1)`. `subprocess.CalledProcessError` is in that tuple specifically so a failing `ffmpeg`/`ffprobe` invocation (bad input file, unsupported codec, etc.) surfaces as a one-line error rather than a raw traceback. Anything outside that set (a genuine bug) still propagates as a traceback — deliberately, so unexpected failures stay loud.
7. **Streaming-friendly transcription.** Both ASR backends return/yield a lazy iterable of `Segment`s; the segment loop in `create_subtitles()` is what actually drives inference (local) or paginates the API response (Scribe). Do not materialize `segments` into a list without reason — that changes when work happens and breaks the progress bar semantics. The degenerate-timings check (the whisper-1 fixed-cadence warning below) respects this constraint by design: it accumulates only two running counters (a total and a near-1.000s tally) inside the loop and warns after it — the check itself holds no list of segments or durations.
8. **Timing is scene-anchored, not per-segment, and drift correction is a bounded loop, not a single fixed retry.** `dub.py:_group_segments` partitions the translated segments into anchor groups: a new group starts whenever `_inter_segment_gap(prev, segment)` exceeds `_GAP_THRESHOLD = 1.5` seconds — that gap is word-level (`next.words[0].start - prev.words[-1].end`) when both segments carry `words`, else the cue-boundary gap (`next.start - prev.end`); a whole-input single group with no internal gap is logged as a WARNING rather than accepted silently. Each group's anchor is its first segment's original ASR start; `synthesise_track` lays a group's clips out via `_layout_group`, each clip pinned to `max(segment.start, prev_placed_end)` — its own ASR start unless the previous clip is still running past it, in which case it floats forward just enough to avoid overlap. This (not a slack-splitting formula) is what stops a group whose speech is shorter than its source span from piling the unused slack up as trailing silence. `dub.py:_corrective_rate(idx, group, current_rate, drift, clips) -> float` computes each pass's rate by *composing* onto the rate the group's current clips were actually synthesised at: `current_rate * _required_rate(measured_speech_total, source_span)`, where `_required_rate()` is the shared unclamped exact-fit-ratio helper — not an absolute target, since a pass's measurement reflects whatever rate the previous pass applied, not 1.0x. The composed rate is clamped to `[0.9, 1.15]` (`_MIN_RATE`/`_MAX_RATE`), intentionally tighter than the ElevenLabs API's own documented `voice_settings.speed` range of `0.7-1.2`; when the clamp binds, a WARNING names the unclamped rate and residual drift, and if the composed rate is unchanged from the one already applied (clamp saturated), the group is skipped rather than repaying for identical audio. Drift itself is measured as synthesised speech total against summed **source speech time** (`_speech_duration`/`_group_speech_span`: word-span `words[-1].end - words[0].start` when available, else the cue span), not the wall-clock cue span — intra-cue pauses no longer drive the corrective rate. `synthesise_track` runs an initial pass synthesising every segment, across all groups, once at rate 1.0, as one flat cross-group batch over a single bounded `ThreadPoolExecutor`; a pure-arithmetic layout pass then computes each group's accumulated drift and, for any group whose drift exceeds `_DRIFT_TOLERANCE = 0.5` seconds, flags it for correction. What follows is a **bounded correction loop** (`_MAX_CORRECTION_PASSES = 3`, wired to `--dub-correction-passes`): each pass submits one flat cross-group batch — only the segments of groups still outside tolerance, at that group's shared clamped rate (`_corrective_rate`, which WARNs with the unclamped rate and residual drift when the clamp binds) — over the same executor, then re-measures each corrected group; a group drops out of the loop as soon as it is back within tolerance, or as soon as a pass fails to reduce its drift (each pass is paid TTS, so a non-improving group is not resubmitted). `--dub-correction-passes 1` bounds correction to a single pass -- it does not reproduce the old fixed phase-A/phase-B behaviour exactly, since the drift metric changed (speech time, not wall-clock cue span) and a non-improving pass is now discarded rather than always kept. Because every group restarts exactly on its own anchor, drift never compounds or crosses a group boundary — a scene with a bad fit doesn't drag the next scene out of sync. There is no `--drift-strategy` flag and no per-segment slot-fitting path any more — see the git history for the original rationale (drift absorbed in inter-scene pauses, not squeezed into every line), the earlier per-segment design this replaced, and the redesign that replaced the fixed phase-A/phase-B structure and the cue-span drift metric with the above.
9. **ffmpeg-presence checking is deliberately duplicated, not a bug to deduplicate.** `cli.py:_check_ffmpeg_tools()` checks for both `ffmpeg` and `ffprobe` on `PATH`; `mux.py:mux_dub` checks only `ffmpeg` (`shutil.which("ffmpeg")`) — it has no `ffprobe` call of its own to guard. This is intentional: `cli.py`'s check is the early, user-facing gate that fails `--dub` before any paid API call is made (ASR/translation/TTS); `mux.py`'s narrower check is a library-level guard for callers that import and invoke `mux_dub` directly, bypassing `cli.py` entirely. Do not remove either check, or widen `mux_dub`'s to match `cli.py`'s, to "deduplicate" them.
10. **Scribe's word-to-segment grouping is an explicit, tunable policy, not an implementation detail.** ElevenLabs Scribe returns word-level timing, not segments, so something must group words into subtitle-cue-sized `Segment`s. `providers/elevenlabs.py:ScribeTranscribe._group_words` does this, breaking a run of words into a new segment on sentence-end punctuation, when the buffered span would exceed `max_segment_seconds` (constructor arg, default `7.0`) or `max_segment_chars` (constructor arg, default `100`), *or when the diarized `speaker_id` changes* (constructor arg `diarize`, default `True` — requested via `diarize=self.diarize` on `speech_to_text.convert`), whichever comes first. This stays as designed — the constants are deliberately callable-overridable, not hardcoded magic numbers, and the speaker-change flush is what gives every cue a single, unambiguous `Segment.speaker`.
11. **Logging over printing.** Each module uses `logging.getLogger("<module>")`; formatting is configured once in `__init__.py`. Use `logger.info` / `logger.warning` / `logger.error`, not `print`.
12. **The local engine stays offline-capable, but not unconditionally any more.** `--engine local` (the default) makes no network calls except Hugging Face model downloads, and needs no API key, **as long as `--voice-match off` is passed**. Any other `--voice-match` value (`auto`, the default, included) now runs a `pyannote.audio` diarisation pass over the source audio, which contacts Hugging Face for the gated `pyannote/speaker-diarization-community-1` model on first use and needs `HF_TOKEN` set with that model's conditions accepted. Any stage set to `elevenlabs` or `openai`, `--dub`, `--managed`, and now `--voice-match != off` on `local`/`openai` ASR, require network access and the corresponding credential.
13. **Voice resolution is a separate module from synthesis, and degrades rather than fails.** `voices.py:resolved_voices` (a context manager, called from `cli.py:create_subtitles` unconditionally whenever `--dub` -- `mode="off"` short-circuits inside it, rather than being special-cased at the call site) yields a speaker -> TTS voice id mapping; `dub.py:synthesise_track`'s `voices` kwarg only ever does a `dict.get(segment.speaker)` lookup — it has no cloning, classification, or preset logic of its own. Every degradation path inside `resolved_voices` falls back rather than raising: too little clean audio to clone falls back to a preset; a failed `clone_voice` call falls back to a preset; a failed classification (`classify_voice` catching `Exception` around the `librosa`/`parselmouth` calls) falls back to the table's `"default"` entry. The only hard failure is `load_preset_table` rejecting a malformed `--voice-preset-table` file up front, before any dub work starts. Cloning is gated on `tts_engine in {"elevenlabs"}` regardless of `--voice-match` value — `--tts-engine openai` never clones, even under `--voice-match clone`, it just always falls through to preset matching for every speaker. Every voice `resolved_voices` clones is registered as it happens and deleted in its own `finally` block unless `keep=True` (wired from `--keep-cloned-voices`) — covering a raise partway through resolution and a raise from the caller's `with` body (the dub itself) identically, since both run the same `finally`.

## 7. Configuration

API keys are loaded from a `.env` file by `cli._load_env()`, called from `main()` only, using `find_dotenv(usecwd=True)` so discovery is anchored to the user's cwd rather than to the installed package; already-exported variables are never overridden, and importing any module still reads no `.env`. `.env.example` documents the three API-key variables. `--voice-preset-table` is the repo's first actual config-file format: a JSON file, validated strictly by `voices.py:load_preset_table` at load time (not deferred to a mid-dub `KeyError`), that replaces the built-in preset voice table wholesale for the TTS engines it names. A missing/invalid token degrades the run (one WARNING, single-voice dub) rather than failing it |

Implicit configuration from the environment of underlying libraries: `HF_HOME`/`HF_HUB_CACHE` control the local model cache location; `device_map="auto"` lets accelerate/torch pick CPU vs GPU for the local translation model. Output paths are not configurable — `.srt` is always `input.with_suffix(".srt")`; `--dub` writes `<input>.dubbed<ext>` (same suffix as the source, muxed locally); `--managed` writes `<input>.dubbed.mp4` (downloaded rendered media, always `.mp4` regardless of the source's suffix — see section 10). `--dub` also creates an intermediate `<input>.dub_audio.mp3` (the assembled, pre-mux audio track from `dub.py:synthesise_track`) — it is deleted automatically once the mux into `<input>.dubbed<ext>` succeeds, and deliberately left on disk when the mux fails, so a failed run doesn't discard the synthesis work.

## 8. Command Structure

Single-command CLI; no subcommands, despite the stale `usage="translation-cli <command> [<args>]"` string in the parser (unchanged from before this port — still misleading, not fixed as it's out of this port's scope).

- `main()` parses args, then calls `create_subtitles()` **positionally** for the first five params (`fpath, audio_lang, srt_lang, whisper_model_name, mt_model_name`) and by keyword for everything added since (`engine`, `asr_engine`, `translation_engine`, `dub`, `managed`, `tts_engine`). Do not reorder the positional params — `main()` depends on that order. Add any new param as a keyword-only addition at the end of the signature (`tts_engine` was appended last, after `managed`).
- `create_subtitles()` is the public, importable API for programmatic use; it accepts `str | Path`. When `managed=True` it short-circuits into `_run_managed()` and returns without touching the transcribe/translate/dub path at all. `asr_engine`/`translation_engine`/`tts_engine` default to `None` and fall back to `engine` when unset (`cli.py`, resolved before any provider is built).
- **Exit codes:** 0 on success; 2 on argparse errors (stdlib default); **1** on `RuntimeError | ValueError | FileNotFoundError | TimeoutError | subprocess.CalledProcessError` raised from within `create_subtitles()` — caught in `main()`, logged as one line via `logger.error`, then `raise SystemExit(1)`. `cli.py:_check_ffmpeg_tools()` (called from `create_subtitles()` as soon as `--dub` is known, before the ASR provider, translation loop, or `voices.py:resolved_voices()` -- which also shells out to ffmpeg to extract speaker samples -- ever run) proactively raises `RuntimeError` if `ffmpeg` or `ffprobe` is missing from `PATH`. `ffmpeg.py:run()`, the shared invocation point used by `dub.py` and `mux.py`, no longer lets a non-zero exit surface as `subprocess.CalledProcessError`: it runs without `check=True` and raises a `RuntimeError` quoting ffmpeg's stderr tail instead. Every ffmpeg *and* ffprobe invocation now goes through it — including `ffmpeg.py:probe_duration()` (shared by `dub.py`, `providers/ffmpeg_align.py`, and `voices.py`), which returns the captured `stdout` — so a failing external tool always surfaces as a stderr-quoting `RuntimeError`. `subprocess.CalledProcessError` remains in the caught set for safety but is no longer raised from anywhere in the package. Any other exception (a bug, not a known failure mode) still propagates as an uncaught traceback — this is intentional, not a gap.

## 9. Subtitle Output Format

SRT formatting lives in `srt.py` now (not inline in `cli.py`), but the sub-second precision changed from before this port:

- `format_timestamp`: converts `seconds` to whole milliseconds (`round(seconds * 1000)`) and formats `HH:MM:SS,mmm` from that — real millisecond cues, not truncated-to-the-second `,000` placeholders. This matters now that Scribe supplies word-level timing; a coarse `,000` cue was tolerable when segment bounds were coarser.
- `format_block(index, start, end, text)`: builds one `"{index}\n{start} --> {end}\n{text}\n\n"` block. `index` is passed in by the caller as `segment.id + 1` (ASR-provided id, not the loop index) — because empty translations are skipped with `continue` in `cli.py`, emitted ids can have gaps, for both engines.
- `srt.py:pad_cue_end(end, next_start)` pads a cue's end by up to `_CUE_PAD = 0.5` seconds toward readability, capped so it never overlaps `next_start` (or uncapped when `next_start is None`, for the final cue). This padding is applied **only at `.srt` write time** — `Segment.start`/`.end` stay word-accurate and unpadded, since those are what `dub.py` groups, anchors, and measures drift against. `cli.py`'s SRT-writing loop carries a one-segment lookahead (holding the previous cue's data, emitting it once the next segment's start is known, flushing the last with `next_start=None`) so padding can be computed without materialising `segments` into a list.
- A single leading space in the translated text is stripped.
- `cli.py` accumulates all blocks in a list and writes once at the end (`srt_file.write_text(..., encoding="utf-8")`) — nothing is written incrementally, so an interrupted run produces no `.srt` file. Unchanged from before this port.

## 10. Timing-Drift and Dub Pipeline (new in this port)

Only relevant when `--dub` is passed. `--dub` requires the TTS stage to resolve to `elevenlabs` or `openai` (`create_subtitles()` raises `ValueError` otherwise — unchanged, still a hard error). A translation stage resolving to `local` is *allowed* under `--dub`: `create_subtitles()` logs a `logger.warning` (MADLAD400 ignores `budget_chars`, so length-budgeting is a silent no-op and fitting degrades to TTS-rate-only) and the run proceeds. ASR can still be `local` under `--dub` regardless.

**Cost:** a group is synthesised once at 1.0x; only a group whose accumulated drift exceeds tolerance enters the correction loop, paying for up to `--dub-correction-passes` (default 3) further re-syntheses of that group's clips at a shared rate, stopping early once it's back in tolerance or a pass fails to improve it. So the paid-TTS-call multiplier is bounded per group, not per segment — a large group that keeps drifting pays for up to `correction_passes` further passes over all its clips, one that stays within tolerance pays once.

1. `cli.py:_budget_chars(start, end, text, output_lang, tts_engine)` derives a character budget as the LARGER of two independently measured lower bounds, not a primary term plus a cap: the expansion-ratio term `len(text) * _EXPANSION_RATIO[output_lang]` (falling back to `_EXPANSION_RATIO["default"]`) estimates how long the translation will naturally run, and the slot-capacity term `duration * _TARGET_SPEAKABLE_CPS[f"{tts_engine}:{output_lang}"]` estimates how many characters the cue's own time span can hold at the measured target-language speaking rate. Both constants replace the former single assumed `_CHARS_PER_SECOND = 15.0` and are measured — `_EXPANSION_RATIO["da"] = 1.036` and `_TARGET_SPEAKABLE_CPS["openai:da"] = 19.822`, from ~3 minutes of short-utterance animated-trailer `en -> da` material, and are explicitly labelled provisional pending a re-fit on feature-length dialogue. `_TARGET_SPEAKABLE_CPS` is the measured *median* tts-1 Danish output rate at 1.0x, not an observed maximum — a slot of `D` seconds physically fits `cps * D` characters of synthesised speech at that rate, so this term is a floor against the TTS engine's own delivery speed, not a plausibility check on the source text. Taking `min()` of the two terms (the old behaviour) starved cues whose source text was sparse relative to a generous slot: measured over 68 real segments, it budgeted half of them below the rate the source actors themselves speak at (median 15.99 chars/slot-second); taking `max()` instead raises the median budgeted rate to 19.65 chars/slot-second (+26%), with all 68 segments now at or above the source rate. Trade-off: since `_TARGET_SPEAKABLE_CPS` is a median, not a maximum, using it as a floor overshoots the slot for roughly half of segments by construction — if the translator fills the larger budget, the failure mode can flip from underrun to overrun. Keyed `"<tts engine>:<target language>"` like its language-keyed neighbour, because speaking rate depends on both and this term now binds on 55 of 68 measured segments — an unmeasured pair would inherit it as the dominant budget term, not a rare ceiling. Only `"openai:da"` is measured; `default` deliberately repeats that same figure rather than inventing a second one, so the table changes no budget today and exists to make the extrapolation visible.
2. The translator is called with that budget (`TranslationProvider.__call__(text, output_lang, budget_chars=...)`). `LLMTranslate` (Claude) and `OpenAITranslate` both use it in the prompt (shared wording from `providers/prompt.py:build_prompt`); `Translate` (MADLAD400) ignores it — no length-control lever exists for that model.
2a. Before synthesis, `create_subtitles()` enters `voices.py:resolved_voices(fpath, dub_segments, tts_engine=..., mode=voice_match, presets=..., keep=keep_cloned_voices)` as a `with` block wrapping the whole `_dub_and_mux()` call (entered unconditionally whenever `--dub`; `resolved_voices` itself short-circuits to an empty mapping and no work for `mode="off"`). This is a one-shot pre-pass over the whole segment list — cloning and classification happen once per distinct `Segment.speaker`, not per segment or per group — and the yielded `voices` dict is threaded into `synthesise_track(..., voices=voices_map)`, which is the only thing that reads it (one `voices.get(segment.speaker)` lookup per segment, in `_layout_group`); `synthesise_track` itself has no cloning or classification logic. `resolved_voices`'s own `finally` block deletes every voice it cloned unless `keep=True`, whether resolution raises partway through, the `with` body (the dub) raises, or both complete normally — there is no separate exception-attribute channel or duplicate cleanup call in `cli.py` any more.
3. `dub.py:synthesise_track`:
   - `dub.py:synthesise_track` partitions the translated segments into anchor groups (`_group_segments`, splitting on `_inter_segment_gap` — word-level when both segments carry `words`, else cue-boundary — exceeding `_GAP_THRESHOLD = 1.5s`; a degenerate whole-input single group is logged as a WARNING) and runs synthesis over one bounded `ThreadPoolExecutor` (`max_workers`, wired to `--dub-workers`, default 1 — serial unless raised) as an initial pass plus a bounded correction loop, rather than a fixed two-phase structure: the initial pass synthesises every segment at rate 1.0 (each TTS call retried up to `_TTS_MAX_ATTEMPTS = 3` times on plain `Exception`, sleeping a full-jitter backoff between attempts — `random.uniform(0, _TTS_BACKOFF_BASE * 2**(attempt-1))` with `_TTS_BACKOFF_BASE = 1.0`, so 1s/2s are window ceilings rather than fixed waits, chosen so workers that collide on a vendor concurrency cap separate on retry instead of waking and re-colliding in lockstep; the required `aligner: AlignmentProvider` call that measures each clip's real speech span has no retry — an aligner exception is the degrade signal `FallbackAlign` acts on), then a pure-arithmetic layout pass (`_layout_group`) computes each group's drift — synthesised speech total against summed source *speech* time (`_group_speech_span`), not wall-clock cue span — and flags any group exceeding `_DRIFT_TOLERANCE = 0.5s` for correction.
   - What follows is a bounded loop of up to `correction_passes` (`_MAX_CORRECTION_PASSES = 3`, wired to `--dub-correction-passes`) passes: each pass re-synthesises only the segments of groups still outside tolerance, at that group's shared corrective rate (`_corrective_rate`, clamped to `[_MIN_RATE, _MAX_RATE] = [0.9, 1.15]`, WARNing with the unclamped rate and residual drift when the clamp binds), re-measures them, and drops a group out of the loop once it's back in tolerance or a pass fails to reduce its drift; clip files are pass-discriminated (`segment_NNNNN_pNN.mp3`) so a rejected pass's audio never sits under a kept clip's stale offsets. `--dub-correction-passes 1` bounds correction to a single pass rather than reproducing the old fixed phase-A/phase-B behaviour exactly -- the drift metric changed and a non-improving pass is now discarded instead of always kept.
   - Every pass gets its clips from `_resolve()`, which is the only path to them -- there is no way to collect results without first waiting: `_resolve()` takes an iterable of per-group batches and flattens them all before waiting, so a pass with several groups' batches aborts across all of them together, not just the group containing the failure. It waits with `concurrent.futures.wait(..., return_when=FIRST_EXCEPTION)`, and on a failure sets a per-`synthesise_track()`-call `threading.Event` abort flag *before* cancelling the still-queued tail — the flag is what stops calls that have not yet issued their vendor request (checked by each worker before its TTS call and before each retry sleep, raising a private `_Aborted` sentinel), which cancelling the tail alone cannot do for tasks already started; it is shared across the whole call's `ThreadPoolExecutor`, so it can also stop an already-submitted task from a *different* batch of the same call, and is never reset within one call. It then classifies every future in one pass (a future that started or finished between `wait()`'s snapshot and the cancel pass is read from its actual outcome, so it can never be miscounted as in-flight) — the five counts (succeeded / failed / aborted / cancelled / still-in-flight) are mutually exclusive and sum to the batch size, but "still-in-flight" is not a final state: those tasks are genuinely still running (possibly already past their own abort check, mid vendor call) and may finish before the `WARNING` accounting for each category is even emitted. A future whose exception is `_Aborted` is counted as `aborted`, not `failed`, and excluded from the set of failures eligible for re-raise, so a worker's cooperative early bail can never itself become the batch's reported cause; because the abort flag cannot interrupt an HTTP request already in flight, only calls not yet issued, a batch where every task has already called the vendor by the time of the abort reports `aborted` as 0 — the same shape of caveat as `cancelled` always had.
   - It re-raises the lowest-submission-index failure among the *real* failures observed during that classification pass — deterministic given that set, but which failures are visible depends on what else completed after `wait()` returned, so this is not a total order over every failure two truly concurrent tasks could raise — the `with ThreadPoolExecutor(...)` block's `shutdown(wait=True)` still lets up to `max_workers` already-running tasks finish, so no worker outlives the exception, but no queued-and-not-yet-started task is submitted to the vendor. This is strictly better than draining the whole batch, not a fixed bound: the actual saving depends on how much of the batch is still unstarted (or, since the abort flag can also cut short a not-yet-issued call from a task that had already started retrying, how much of it has not yet called the vendor) by the time the failing task's jittered retry backoff elapses and it finally raises, since other workers keep completing meanwhile — a batch short enough to drain inside that window leaves nothing to cancel or abort and `_resolve()` is a correct no-op.
   - `_layout_group` places a group's clips pinned to their own ASR start: each clip is placed at `max(segment.start, prev_placed_end)` — its own source start unless the previous clip is still running past that point, in which case it floats forward just enough to avoid overlap. This is what stops a group whose speech is shorter than its source span from piling the unused slack up as trailing silence. Results are collected by submission index, and per-group log lines come from the layout passes, so output and log order are independent of completion order across the worker pool. Every group restarts exactly on its own anchor, so drift never crosses a group boundary.
   - The real speech-span measurement itself lives in `providers/ffmpeg_align.py` (`SilenceAlign`, `DurationAlign`) and `providers/fallback.py:FallbackAlign`, not in `dub.py` — see below.
4. `_assemble_timeline` builds an ffmpeg `filter_complex` that delays each clip to its placed offset and mixes them onto one continuous track (`adelay` + `amix`); each clip's leading/trailing TTS padding is dropped first via a per-input `-ss <trim_start>`/`-t <speech_len>` offset pair, so only the measured speech span lands on the timeline. `synthesise_track` then derives `speech_spans` from the same placements: `dub.py:_speech_spans()` takes each placement's `[start, start + speech_len]`, pads it by `_SPAN_PAD = 0.15s` on both sides (the `volume` automation is a hard step, not a ramp, so the pad does not soften the transition -- it only moves where the step falls, starting the duck slightly before the dub's speech and releasing it slightly after, rather than snapping exactly on the measured boundary), sorts, and coalesces adjacent/overlapping windows so `mux.py` never sees two spans that touch or cross. This list is the function's second return value.
5. Optionally, `separate.py:Separate` — when `--separate-background` is passed, `cli.py:_dub_and_mux` constructs `Separate()` and calls it on the source `fpath` before muxing, writing an accompaniment (no-vocals) wav into a `tempfile.mkdtemp()` directory rather than next to the user's media. `demucs` is a declared hard dependency, so an `ImportError`/`ModuleNotFoundError` anywhere on the separation path always propagates and fails the run, rather than degrading — this covers both the top-level `from movie_subtitles.separate import Separate` import and one raised by `Separate.__init__`'s own lazy `torch`/`demucs.api` imports: an install missing either is broken, and silently degrading would only produce a worse output bed. `cli.py:_dub_and_mux`'s `try`/`except Exception` around the construction and the call carries a leading `except ImportError: raise` so an import failure is re-raised before the broader handler can catch it. Only a genuine *runtime* failure (unreachable model weights, a bad input file, a decode/inference error) is caught there, logged as one WARNING, with `background_path` staying `None` and the run falling straight through to the ordinary duck-and-mix path below. That temp dir, like the intermediate dub audio track, is removed in a `finally` regardless of outcome. `--managed --separate-background` raises `ValueError` up front, before any ASR/translation work starts, since ElevenLabs's managed job already handles background preservation itself.
6. `mux.py:mux_dub`:
   - `mux.py:mux_dub` overlays that finished audio track over the source video. It no longer drops the original audio: `ffmpeg.probe_audio_format(video_path)` returning `None` (a single `ffprobe -select_streams a:0` query that also supplies the channel layout/sample rate used below) decides which of two command shapes to build, both assembled from one shared argv tail — only the `-filter_complex` presence and the audio `-map` target (`1:a:0` vs `[out]`) differ.
   - With no audio stream, it falls back to the old dub-only mapping (`-map 0:v:0 -map 1:a:0 -c:v copy -c:a <codec>`) — `background_path` is ignored (and logged) in this branch too, since there is nothing in the source's own layout/rate to match it to.
   - With one, `mux_dub` first resolves which audio branch to duck and to what level: `background_path` (`Separate`'s accompaniment wav, given as a keyword-only argument), when not `None`, becomes a third ffmpeg `-i` input and replaces the source's own `0:a:0` as the "original" branch (label `2:a:0` instead); otherwise the source's own `0:a:0` is used, unchanged from before `--separate-background` existed. `duck_level` is keyword-only and defaults to `None`, a sentinel resolved as: an explicit value always wins; otherwise `_SEPARATED_DUCK_LEVEL = 0.6` when `background_path` is given (the original dialogue is already gone via separation, so ducking only needs to buy the dub headroom over loud music, not fight a second voice) or `_DUCK_LEVEL = 0.25` otherwise — this is why the CLI's own `--duck-level` argparse default had to change from a literal `0.25` to `None`: which of the two applies depends on whether separation succeeded, which argparse cannot know at parse time. It then builds a `-filter_complex` that:
     - (a) chains one or more `volume=...:eval=frame` filters over the resolved original/background label — one per chunk of at most `_MAX_SPANS_PER_FILTER = 200` spans (`_ducking_chain`, which returns both the chained filter statements and the label carrying the result), since `volume`'s expression is a single argv token and a filter built from hundreds of `between(t,start,end)` terms risks exceeding practical expression/argv limits; each chunk's spans are disjoint from every other chunk's because they're globally coalesced first, so multiplying by `1.0` outside a chunk's own spans never double-ducks — attenuating that branch to the resolved `duck_level` inside every `speech_spans` window and leaving it at `1.0` elsewhere;
     - (b) applies `_MIX_INPUT_GAIN = 0.7` to both the (possibly ducked) bed and the dub track before mixing, because `amix=normalize=0` — used instead of the default `normalize=1` so the dub doesn't get scaled down — does not itself guard against two full-scale inputs clipping when summed;
     - (c) normalises both branches to one explicit format with `aformat=sample_fmts=fltp:sample_rates=...:channel_layouts=...`, taken from the *source's* own first audio stream via `ffmpeg.probe_audio_format(video_path)` (falling back to `_UNKNOWN_CHANNEL_LAYOUT_FALLBACK = "stereo"` / `_UNKNOWN_SAMPLE_RATE_FALLBACK = 48000` when ffprobe reports an empty or `unknown` layout, which would be an invalid `aformat` argument) — even with `background_path` given, this target still comes from the source, not from the separated stem, so the output still matches the source's own layout/rate regardless of what Demucs produced internally (44.1 kHz stereo) — `amix` will negotiate a common format itself, but implicitly and version-dependently, and targeting the source's format rather than a fixed one is what keeps a 5.1 soundtrack 5.1 instead of downmixing it to stereo;
     - (d) sums them with `amix=inputs=2:normalize=0` and maps `0:v:0` plus the mix output. `speech_spans` defaults to `None`/empty, which mixes the bed in unducked throughout rather than omitting it.
   - In both shapes, the audio codec comes from `ffmpeg.audio_codec_for(suffix)` — WebM admits only Vorbis/Opus, so `.webm` gets `libopus` and everything else AAC; the video track is always stream-copied, so the source's video codec is by definition already legal in its own container — and the result is written to `<input>.dubbed<ext>`.
   - No `-shortest`: the video's full duration is authoritative, so a synthesised track that ends before the video's tail does not truncate the video (verified with synthetic media: a 10s video + 3s audio track muxes to a 10s output).
   - `cli.py:_check_ffmpeg_tools()` raises `RuntimeError` up front (before any dub work starts) if either `ffmpeg` or `ffprobe` is missing from `PATH`.
   - `cli.py:_build_aligner()` always returns an `AlignmentProvider` — never `None` — by assembling `providers/fallback.py:FallbackAlign([Align()?, SilenceAlign(), DurationAlign()])`:
     - `Align()` (ElevenLabs Forced Alignment) is omitted (INFO log) when `ELEVENLABS_API_KEY` is unset, or on any client-construction failure (WARNING log), leaving `SilenceAlign` → `DurationAlign` as the chain. `FallbackAlign` tries each tier in order per call, and gates each tier's very first call behind a per-tier lock so exactly one thread makes it while any others that arrive concurrently block on the outcome — a tier broken from the start costs at most one failing vendor call for the whole run, not one per worker thread that reaches it before the latch takes effect.
     - That bound is narrower than it may look: a tier that succeeds for a while and then starts failing (a vendor outage mid-run) is already past its gate, so up to one failing call per thread concurrently calling it can land before `_latch_off_once` disables it — bounded by the worker count, once per tier, not the unconditional single-call bound the initial gate gives a tier that never worked. That first call raising latches the tier off for the rest of the run (WARNING, once); once a tier's first outcome is known, every later call to it runs fully unserialised. It logs each tier it actually settles on exactly once (INFO) — a run that starts on tier 1 and later degrades to tier 2 logs both lines, at most one per tier, not once per process — and raises `RuntimeError` (chained from the last tier's exception) only once every tier is exhausted — `DurationAlign` never fails, so in practice the chain always bottoms out.
     - Every read and write of its `_disabled`/`_settled` state is guarded by a second, shared `threading.Lock` (distinct from the per-tier gate locks above) because `dub.py` now calls it concurrently across the worker pool; unlike a gate lock, this shared lock is acquired only for the read/write itself and is never held across a provider call, so the steady-state (post-latch) call path stays unserialised. Forced Alignment is a nice-to-have for tighter clip trimming, not a hard requirement for `--dub`.

`dubbing.py:ManagedDub` (the `--managed` path) is architecturally independent of all of the above — it does not touch `srt.py`, `dub.py`, `mux.py`, or any provider. It only talks to the ElevenLabs Dubbing job resource (`dubbing.create` / `.get` / `.audio.get`), polling on a fixed interval up to a timeout, and streams the rendered download to `<input>.dubbed.mp4`. The `.mp4` extension is fixed regardless of the source file's suffix: the installed SDK's own docstring for `dubbing.audio.get` (`.venv/lib/python3.12/site-packages/elevenlabs/dubbing/audio/client.py`, matching https://elevenlabs.io/docs/api-reference/dubbing/audio/get.md) states it "Returns dub as a streamed MP3 or MP4 file" — for a video source it renders an MP4 container, not necessarily whatever container the source used, so writing the bytes under the source's original suffix (e.g. `.mov`, `.mkv`) would mislabel the file.

## 11. Summary & Key Architectural Decisions

- Three vendors (`local`, `elevenlabs`, `openai`) selectable per stage via `--asr-engine`/`--translation-engine`/`--tts-engine`, `--engine` a shorthand for all three, plus one bypass path (`--managed`), unified only at the `create_subtitles()` orchestration level in `cli.py`.
- `providers/base.py` Protocols (`ASRProvider`, `TranslationProvider`, `TTSProvider`, `AlignmentProvider`) plus the shared `Segment` dataclass are the contract that keeps `srt.py` and `dub.py` provider-agnostic.
- `--engine elevenlabs` alone spans two vendors and is rejected: ElevenLabs (ASR, TTS, Dubbing) has no standalone translation endpoint, so `--translation-engine {anthropic,openai,local}` must be passed explicitly. This is documented in the README as a finding, not hidden.
- Timing is scene-anchored, not per-segment: segments are grouped into anchor groups by inter-segment silence gap (`_GAP_THRESHOLD`, word-level when both segments carry `words`, else cue-boundary), and each group's clips are pinned to their own ASR start, floating forward only on overrun (`max(segment.start, prev_placed_end)`). Drift is tracked and corrected at group granularity, not per segment, and is measured against summed source *speech* time, not wall-clock cue span — a group whose accumulated drift exceeds `_DRIFT_TOLERANCE` enters a bounded correction loop (`--dub-correction-passes`, default 3, `_MAX_CORRECTION_PASSES` in `dub.py`), re-synthesised at a shared clamped rate (`_MIN_RATE`-`_MAX_RATE`) and re-laid-out each pass, dropping out once back in tolerance or once a pass fails to improve it; `--dub-correction-passes 1` bounds correction to a single pass, not an exact reproduction of the old single-retry behaviour (the drift metric changed from wall-clock cue span to speech time, and a non-improving pass is now discarded rather than always kept). Every group restarts exactly on its own anchor, so drift never crosses a group boundary. Clip length is measured as the real speech span via `providers/fallback.py:FallbackAlign` (ElevenLabs Forced Alignment → `providers/ffmpeg_align.py:SilenceAlign` → `DurationAlign`, degrading in that order and required by `synthesise_track`'s `aligner` kwarg) rather than trusted as the container duration, and leading/trailing TTS padding is trimmed from the timeline via per-input `-ss`/`-t` offsets. Synthesis itself runs concurrently over one bounded `ThreadPoolExecutor` (`--dub-workers`, default 1 — serial unless raised) as an initial pass at 1.0x followed by the bounded correction loop (each pass a flat cross-group batch over only the groups still outside tolerance), with results collected by submission index so output/log order is independent of completion order. Each pass fails fast via `dub.py:_resolve()`, which flattens that pass's per-group batches before waiting: the first exception cancels the still-queued tail across all of them (already-running tasks finish) and re-raises the lowest-submission-index failure among the failures visible at that point, instead of draining every queued TTS call before the failure surfaces.
- Known-cause errors (`RuntimeError`, `ValueError`, `FileNotFoundError`, `TimeoutError`) are caught once in `cli.py:main()` and turned into a one-line message + `SystemExit(1)`; anything else still traces back.
- Defaults are duplicated between argparse and every public callable's signature that shares them, not just class `__init__`s — e.g. the `--dub-workers` default of 1 legitimately exists in argparse, in `create_subtitles()`, and in `dub._MAX_WORKERS`; `--dub-correction-passes`' default of 3 is likewise duplicated across argparse, `create_subtitles()`, and `dub._MAX_CORRECTION_PASSES`. This is deliberate, not a defect to collapse; change every copy together.
- `create_subtitles()`'s original five params are positional; new params are keyword-only at the end — do not reorder.
- Ruff (format + `E,F,I,UP,B,SIM`, line length 100) is the only enforced standard, and the only CI job.
- uv owns the environment; `uv.lock` is committed and must be updated alongside any `pyproject.toml` dependency change.
- There are no tests. There is now an error-handling layer at the `main()` boundary, but nowhere else — provider code still lets unexpected exceptions propagate.
- Burned-in subtitles are **not** advertised in the README as of this port; `.srt` and (with `--dub`) a dubbed video are the only outputs (`--dub` also writes and then deletes an intermediate `<input>.dub_audio.mp3`, kept only if the mux fails — see section 7).
- `providers/openai_.py:OpenAITranscribe` defaults to `whisper-1`, not `gpt-4o-transcribe`. An early design draft named `gpt-4o-transcribe` as the intended default; that was a mistake caught during implementation — `gpt-4o-transcribe` supports neither `response_format="verbose_json"` nor segment/word timestamps, and this entire pipeline (every `.srt` cue, every dub timing slot) is derived from segment timings, so `whisper-1` is the only model that can drive it. Do not "fix" the default back toward the spec's original choice — that guidance still holds. But `whisper-1`'s own segment timestamps are not fully reliable either: on one music-heavy, dialogue-sparse trailer, 98 of its 106 returned segments came back as exactly uniform 1.000s spans, chained contiguously, with the model visibly looping on non-speech audio (dozens of consecutive 1.000s segments all transcribed as `"Ow!"`). This was confirmed as vendor behaviour, not a bug in `_yield_segments`'s mapping — the distortion is present in the raw API response before that function sees it, and it reproduces the timings faithfully. Because every `.srt` cue and dub slot derives from these boundaries, this degrades the primary output silently, not just dub timing. This has been observed on one clip, not systematically characterised across content types; `--asr-engine elevenlabs` is the documented workaround on music-heavy or dialogue-sparse material. The run now self-warns when the segment-duration distribution matches this signature (more than 11 segments near-1.000s, making up over half of all segments; the thresholds live as named constants in `cli.py`), so the limitation no longer fails silently. See `providers/openai_.py` for the fuller note at the source.
- The parser's `usage=` string is stale (pre-existing, not touched by this port); the CLI has no subcommands.
- README result numbers (ASR benchmark, TTS quality, unfittable-segment count, build-vs-buy verdict) are explicit `TBD` placeholders as of this port — no API key or media clip was available in the environment this port was built in. Do not treat any number in the README as measured until the repo owner has actually run the commands it documents.
